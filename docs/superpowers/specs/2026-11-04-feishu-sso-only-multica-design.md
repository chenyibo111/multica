# 飞书 SSO 专属账号接入 Multica 设计

## 目的与已确认的要求

- 飞书测试企业成员通过现有 `feishu-sso` 登录 Multica；首次登录创建全新的 Multica 用户，后续登录回到同一用户。
- 即使工作邮箱与已有 Multica 用户相同，也创建独立用户，不按邮箱合并。
- 飞书创建的用户只能用飞书 SSO 登录该用户。现有账号继续使用已有的邮箱验证码和 Google 登录。
- 在 SSO 执行“退出所有项目”后，Multica 的网页、桌面端和 CLI 会话在下一次受保护请求时立即失效。
- Multica 从 `internal/main` 的 `feat/feishu-sso-only-login` 分支开发；SSO 从 `master` 的 `feat/multica-oidc-email` 分支开发。

## 现状与约束

- SSO 已核验 `tenant_key`，以飞书应用 ID 与 `open_id` 生成稳定 OIDC `sub`。通讯录接口现已获准读取工作邮箱；两名测试成员的 `email` 都有值。SSO 当前没有解析或发布邮箱声明。
- Multica 的 `user.email` 为 `UNIQUE NOT NULL`。验证码和 Google 登录都按邮箱查找或创建用户。Multica 签发自己的 JWT，默认有效期较长并可续期；目前退出仅清除 Cookie，没有服务端撤销机制。CLI 的浏览器登录拿到 JWT 后会自动签发 PAT，桌面端守护进程也使用 PAT，不能只撤销 JWT。
- Multica 以用户邮箱显示资料、发送邀请和查找待接受邀请。同邮箱独立用户会使这些查询产生歧义，必须同时处理。
- 本机 Hydra 的浏览器地址是 `http://localhost:4444`，Multica API 在 Docker 中运行。当前 SSO Go 服务只监听主机的 `127.0.0.1:9000`；两个后端需要明确的容器网络路径，令牌中的 OIDC `iss` 仍必须匹配浏览器看到的发行者。

## 考虑过的方案

1. **继续以邮箱作为用户键。** 改动少，但会合并现有账号，违反“全新独立账号”。不采用。
2. **为飞书用户生成假邮箱，另存真实工作邮箱。** 可保留现有唯一约束，但假邮箱容易流入用户界面、邀请、通知和其他集成；需要大范围梳理邮箱字段。暂不采用。
3. **以 OIDC 身份作为飞书用户键，允许不同登录类型的用户共享邮箱。** 保留真实邮箱作为资料，明确限定邮箱登录只匹配原有账号，并修正邀请的账号选择。采用此方案。

## SSO 改动

- 在飞书客户端中解析通讯录接口的 `email`，添加到成员身份结构。邮箱为空不阻止飞书身份认证。
- 在 Hydra 登录上下文中加入非空 `email`；同意 `email` scope 时，向 ID Token 发布 `email` 和 `email_verified: false`。飞书管理员填写的工作邮箱不能视为用户本人已验证的邮箱。保持 `sub` 和租户校验规则不变。
- 在客户端登记脚本中加入 Multica 专用 OIDC 客户端、准确的回调与退出地址、`openid profile email feishu_identity` scope 和 PKCE。开发环境的重定向地址按 Multica 实际公开端口配置，不硬编码到其他项目客户端。
- 更新测试，覆盖有邮箱、空邮箱、字段缺失以及未请求 `email` scope 时的声明行为。

## Multica 身份与数据模型

- 给 `user` 增加登录类型，现有用户默认 `local`，飞书用户为 `feishu`。飞书用户记录经验证的 OIDC `issuer` 与 `subject`；二者组合唯一且不可由用户编辑。
- 保留 `email TEXT NOT NULL` 和面向前端的字符串字段，移除全局邮箱唯一约束。对 `local` 用户建立部分唯一索引以保持原有邮箱登录语义；飞书用户允许与本地用户或其他飞书用户共享邮箱。无邮箱的飞书用户暂存空字符串，并跳过依赖邮件地址的功能。
- 用独立的单语句 `CREATE INDEX CONCURRENTLY` 迁移文件建立新索引，再移除旧约束；按仓库规则重新生成 sqlc。
- 飞书回调只用 `(issuer, subject)` 查找账号。首次登录在事务中创建 `feishu` 用户并写入身份键；并发首次登录由唯一索引收敛到同一用户。后续登录可更新姓名和邮箱；邮箱变化不改变用户 ID、工作区和邀请绑定。
- 验证码与 Google 登录的邮箱查询只返回 `local` 用户；在签发 JWT 前再检查登录类型。若邮箱仅对应飞书用户，不能借这些入口创建或进入该飞书账号，并返回明确的“请使用飞书登录”错误。若同邮箱已有 `local` 用户，仍可登录该独立的本地账号。

## 登录与客户端流程

1. Multica 网页登录页显示飞书登录入口。后端生成 `state`、`nonce` 和 PKCE 参数，浏览器进入 Hydra，再由 SSO 重定向到飞书。
2. Multica 回调在服务端交换授权码，验证 ID Token 签名、`iss`、`aud`、有效期、`nonce`，并核对预期的飞书租户与应用身份。验证通过后按 `(issuer, subject)` 查找或创建用户，签发 Multica 自己的会话 Cookie/JWT。
3. 网页回到原先的安全相对路径或现有引导流程。桌面端和 CLI 沿用浏览器登录与令牌交接机制，但必须将回调来源与必要参数完整地带过 OIDC 往返；从已登录网页签发的交接令牌保留 SSO 会话关联。CLI 接到 JWT 后照常签发 PAT，守护进程也照常从桌面会话签发 PAT。
4. 配置项包括启用开关、OIDC 发行者、客户端 ID、回调地址、容器内的令牌/JWKS 访问地址，以及 SSO 内部会话查询地址和服务密钥。开发配置保留在忽略的本地 `.env`，示例文件只写占位符。

### 本地 Docker 连通性

- 将 SSO Go 服务加入它自己的 Compose：容器内监听 `0.0.0.0:9000`，仅把主机 `127.0.0.1:9000` 发布给浏览器；数据库和 Hydra 管理 API 使用该 Compose 网络中的 `postgres`、`hydra` 服务名。
- 将 Multica 后端容器额外接入 SSO Compose 的开发网络。后端通过 `http://hydra:4444` 交换授权码和获取 JWKS，通过 `http://sso:9000` 查询会话状态；浏览器继续使用 `http://localhost:4444` 与 `http://localhost:9000`。
- OIDC 校验器将预期发行者固定为 `http://localhost:4444/`，但从容器可达的 JWKS 地址取密钥；不能把内部 `hydra` 主机名当成令牌 `iss`。SSO 自身的令牌校验也按同一规则区分公开发行者与内部 JWKS 地址。
- Compose 的跨项目网络连接只作为本地开发配置。生产环境改用可被浏览器和后端访问的正式 HTTPS 域名与独立网络配置。

## 邀请与同邮箱账号

- 邀请一名已存在的用户时，以 `user_id` 锁定目标账号；同邮箱对应多个用户时，管理界面必须让邀请人选择目标账号，不静默选中本地或飞书账号。
- 接受、拒绝和列出邀请时，凡已有 `invitee_user_id` 的邀请只认该用户 ID，不能靠相同邮箱让另一账号领取。
- 只有邮箱、没有目标账号的历史邀请继续按现有本地账号规则处理。飞书邮箱是管理员录入、未由用户本人验证，因此不自动将这类邀请授予飞书账号。飞书成员首次登录创建账号后，邀请人可选择该账号发送定向邀请。
- 没有邮箱的飞书用户可登录并创建自己的工作区；邮件通知和按邮箱邀请需等管理员补充邮箱后使用。

## 统一退出与撤销

- Multica 签发给飞书用户的所有交互式 JWT 都包含经验证的 Hydra `sid`；网页交接给桌面端和 CLI 的新 JWT 继承这一关联。原有本地用户的 JWT 不受影响。
- `personal_access_token` 增加可空的 SSO `sid`。从飞书会话签发的 CLI、桌面守护进程和手工 PAT 都继承该 `sid`；从已有飞书 PAT 再签发 PAT 时继续继承。飞书账号不能获得缺少 SSO `sid` 的人类 PAT。原有本地账号的 PAT 不变。
- Multica 的受保护请求在接受飞书 JWT **或 PAT** 前，使用服务密钥向 SSO 的内部会话状态接口查询该 `sid`。PAT 缓存命中也必须查询撤销状态，不能因为缓存而继续放行。被撤销时返回 401；SSO 或撤销数据库不可用时返回可重试的 503，并拒绝访问。PAT 续期同样受此检查约束。
- Multica 的“退出”从浏览器进入 Hydra 的结束会话流程，SSO 撤销 `sid`，再回到 Multica 退出页。退出页不自动重新登录。桌面端和 CLI 清除本地令牌；统一退出后未清理的旧 JWT/PAT 也会在下一次请求被拒绝，守护进程无法继续用旧 PAT 接入。
- 不依赖 Hydra 异步后端退出通知来保证即时失效；可登记通知地址用于后续优化，但中央撤销状态是正确性依据。每次受保护请求增加一次内部查询，这是即时退出的明确运行成本。

## 验证与交付

- SSO 单元测试和真实飞书测试成员联调：邮箱声明、稳定 `sub`、租户拒绝、退出撤销。
- Multica 数据库测试：两个用户共享邮箱、同一 `issuer+sub` 重复登录、并发首次登录、本地与飞书登录隔离、邮箱变化、邀请目标隔离。
- 浏览器端到端：新账号、同邮箱本地账号并存、网页登录、桌面端与 CLI 交接，以及统一退出后 JWT、CLI PAT、桌面守护进程 PAT 的下一次受保护请求返回未登录。覆盖 PAT 缓存命中和续期路径。
- 分别在两个开发分支提交实现和验证结果。部署前核对 Docker 网络地址、回调白名单和本地机密配置。

## 边界

- 该设计保证 SSO 撤销后的下一次请求失效；已在客户端显示的内容不会被远程擦除。已签发给运行中智能体的短期任务令牌不是人类会话，仍按现有到期规则处理。
- 飞书成员离开企业后的即时禁用、邮箱所有权验证和跨应用身份迁移不在本次范围内。登录时仍需通过 SSO 的租户和应用校验。
