# 飞书单 Bot 主动通知设计

## 目的

本地开发环境中，一个工作区使用一个已连接的飞书应用 Bot。成员继续通过该 Bot 与其对应的智能体对话；Multica 同时把该成员的任务分配、提及、状态变化和执行失败通知发到同一 Bot 的私聊。

## 现状

- 飞书入站消息、智能体回复、成员与 Bot 的账号绑定已经存在。Bot 与智能体一对一。
- `inbox:new` 事件在站内通知入库后发布，通知偏好和收件人过滤已在生成通知时处理。
- `channel_user_binding` 存有该 Bot 下的成员 `open_id`。现有飞书 HTTP 客户端已经能按 `open_id` 发送绑定提示，但普通消息发送仅支持 `chat_id`。
- 飞书事件使用长连接。本地 API 只需能向外访问飞书，无需公网入口。通知链接中的 `localhost` 仅能在本机打开。

## 投递规则

1. 只处理 `inbox:new` 中收件人为 `member` 且类型为 `issue_assigned`、`mentioned`、`status_changed`、`task_failed` 的通知。完成后的任务状态变化沿用已有 `status_changed` 事件；不另造完成通知。
2. 工作区恰好有一个活动飞书 Bot 时，才启用主动通知。没有 Bot 或有多个 Bot 时保持站内通知，记录诊断日志，不猜测发送者。
3. 收件人必须是当前工作区成员，并且绑定到这一 Bot。没有绑定时保持站内通知，不自动按邮箱或 SSO 的其他飞书应用 `open_id` 猜测身份。
4. 使用该 Bot 的凭据向收件人 `open_id` 发私聊文本。正文包含通知类型、标题、简短内容及可用时的站内链接。用户输入按纯文本处理，不解释为 Markdown。
5. 投递失败不能使任务或站内通知写入失败。首版为单实例本地开发的尽力投递，失败写日志，不承诺断电后补发或多实例一致性。

## 范围

- 只改 Multica；不改 `feishu-sso`。
- 不增加新的飞书应用、成员自动绑定、群发、额外通知设置或 GitHub webhook。
- 本地验收：一个 Bot、两名已绑定成员；由一名成员分配任务给另一名成员，收件人在飞书私聊和站内收件箱各收到一次通知；未绑定成员只收到站内通知。
